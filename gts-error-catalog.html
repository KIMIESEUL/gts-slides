에러 메시지 재설계 3원칙

1. 무엇이 일어났는지 말하라
"Error occurred" 대신 구체적인 원인을 사용자 언어로 설명. 에러 코드는 유지하되, 사람이 읽을 수 있는 설명을 반드시 동반.
Nielsen #9 — Help users recognize, diagnose, and recover from errors
2. 어떻게 해결하는지 알려줘라
서비스 리포트 3,750건에서 추출한 실제 해결 패턴을 3단계 조치로 구조화. 고객이 직접 시도할 수 있는 조치 → 지사 대응 → HQ 에스컬레이션 순서.
Nielsen #10 — Help and documentation
3. 심각도를 구분하라
즉시 중단 필요(Critical) vs 계속 사용 가능(Warning) vs 참고 사항(Info)을 시각적으로 구분. 모든 에러를 동일하게 표시하면 사용자는 전부 무시하거나 전부 두려워한다.
Nielsen #1 — Visibility of system status
