CRM 서비스 리포트 구조화 프로젝트

AI가 학습할 수 있는 형식으로 케이스 리포트를 표준화하여, 유사 케이스 자동 매칭 · 해결책 추천 · 반복 이슈 사전 예방을 실현합니다

1 스크린샷 대신 텍스트로 써라

AI는 이미지 안의 텍스트를 직접 읽지 못합니다. 에러 메시지, 로그, 설정값은 반드시 텍스트로 복사해서 붙여넣어야 AI가 검색하고 패턴을 찾을 수 있습니다.

현재 방식
에러 화면 스크린샷 첨부 (이미지에 에러 메시지가 있지만 AI는 읽을 수 없음)
AI 최적화
에러 메시지: "NullReferenceException at KYInspection.FOV.CalcOffset() Line 342: object reference not set"
팁: 스크린샷은 참고용으로 남기되, 핵심 정보(에러 메시지, 설정값, 로그)는 항상 텍스트로 함께 작성하세요.

2 증상과 원인을 분리해서 써라

하나의 문장에 증상, 원인, 해결을 섞어 쓰면 AI가 각각을 구분하지 못합니다. "무엇이 발생했는지"와 "왜 발생했는지"를 명확히 나눠서 작성하세요.

현재 방식
Calibration 하고 나서 Fiducial이 안 잡혀서 FOV 좌표를 다시 설정했더니 해결됨
AI 최적화
증상: Calibration 후 Fiducial 인식 실패 원인: Calibration 시 FOV 좌표 초기화 되나 재설정 프로세스 누락 해결: FOV 좌표 수동 재설정 후 정상

3 재현 절차를 순서대로 써라

AI가 동일 증상의 케이스를 자동으로 묶으려면, 어떤 순서로 했을 때 문제가 생기는지 명확한 단계가 필요합니다.

현재 방식
JOB을 열고 Calibration 후에 Component를 추가하면 문제 발생
AI 최적화
재현 절차: 1. AOI GUI 실행 2. JOB 열기 (기존 JOB) 3. Calibration 수행 (Full Cal) 4. Component 추가 → Apply 5. GUI 응답 없음 (Hang) 발생

4 고정된 분류값을 사용해라

같은 문제를 "GUI 멈춤", "화면 정지", "프리징", "응답 없음"으로 제각각 쓰면 AI는 같은 문제인지 모릅니다. 정해진 카테고리와 용어를 사용하세요.

현재 방식
카테고리: 없음 (자유 서술) "GUI가 먹통이 됨" "화면이 안 움직여요" "프로그램이 멈췄습니다"
AI 최적화
카테고리: GUI/UI 하위: Stability 증상 키워드: GUI Hang 근본 원인: SW 버그 해결 방법: SW 패치
팁: 리포트 작성 탭의 드롭다운 항목을 사용하면 자동으로 통일된 분류값이 적용됩니다.

5 환경 정보를 빠뜨리지 마라

같은 증상이라도 제품, SW 버전, 고객사에 따라 원인이 다릅니다. AI는 이 환경 정보를 조건으로 사용해서 더 정확한 답을 찾습니다.

현재 방식
고객사에서 에러 발생했다고 연락옴. 확인해보니 설정 문제였음.
AI 최적화
제품: AOI SW 버전: 3.2.1.4 고객사: Samsung SDI (VIP) 지역: Korea OS: Windows 10 21H2

6 해결 방법을 구체적으로 써라

"해결됨"만 쓰면 AI는 아무것도 배우지 못합니다. 정확히 어떤 파일/설정/값을 어떻게 변경했는지 써야 다음에 같은 문제가 왔을 때 AI가 답을 줄 수 있습니다.

현재 방식
설정 변경 후 해결됨
AI 최적화
해결 상세: 1. AoiGuiSetup.ini 열기 2. [Memory] 섹션 MaxHeapSize=2048 → 4096 변경 3. AOI GUI 재시작 4. 동일 JOB → 정상 동작 확인

7 AI용 메타데이터를 추가해라

난이도, 재발 가능성, Self-Resolution 가능 여부, 키워드 같은 메타 정보는 AI가 케이스를 분류하고 우선순위를 정하는 데 핵심입니다.

현재 방식
(메타 정보 없음) 그냥 케이스 닫기
AI 최적화
난이도: 중 재발 가능성: 높음 Self-Resolution: 가능 키워드: Memory, HeapSize, GUI Hang 유사 케이스: CAS-00042, CAS-00105
팁: 특히 Self-Resolution 가능 여부는 고객이 스스로 해결할 수 있는 케이스를 AI가 자동 분류하는 핵심 기준이 됩니다.

요약: AI가 학습 잘 하는 리포트 7원칙

  1. 텍스트로 써라 — 스크린샷 속 텍스트는 AI가 못 읽는다
  2. 증상/원인/해결을 분리해라 — 한 문장에 섞지 마라
  3. 재현 절차를 단계별로 써라 — 1, 2, 3 순서대로
  4. 고정된 분류값을 써라 — 같은 문제는 같은 용어로
  5. 환경 정보를 빠뜨리지 마라 — 제품, 버전, 고객사
  6. 해결 방법을 구체적으로 써라 — 파일명, 설정값까지
  7. 메타데이터를 추가해라 — 난이도, 재발, 키워드

현재 vs 구조화 리포트

현재 방식의 한계
- 자유 서술형 텍스트 (비정형) - 에러 정보가 스크린샷 안에 존재 - 카테고리/분류 없음 - 해결 방법: "설정 변경 후 해결" - 메타데이터 없음 → AI가 학습 불가, 검색 불가
구조화 리포트
- 정형화된 JSON 필드 - 에러 메시지 텍스트 복사 - 통일된 카테고리 분류 체계 - 해결: 파일명 + 설정값 + 단계 - 난이도, 키워드, 재발 가능성 → AI 즉시 학습, 패턴 분석 가능

핵심 효과

🔍

유사 케이스 자동 매칭

구조화된 카테고리, 증상 키워드, 에러 메시지가 있으면 AI가 과거 케이스에서 동일/유사 사례를 자동으로 찾아줍니다. 엔지니어가 CRM을 수동으로 검색하며 시간을 소비할 필요가 없어집니다.

케이스 검색 시간 대폭 단축
🤖

AI 자동 답변 품질 향상

증상/원인/해결이 분리되어 있으면 AI가 "이 증상 → 이 원인 → 이 해결법" 패턴을 학습합니다. 데이터가 100건, 1000건 쌓일수록 AI 추천 정확도가 올라갑니다.

정확한 해결책 추천 가능
⚡

Self-Resolution 비율 증가

난이도 "하" + Self-Resolution 가능 케이스가 분류되면, 고객이 직접 해결할 수 있는 가이드를 자동 생성할 수 있습니다. TS 엔지니어의 단순 반복 업무가 줄어듭니다.

단순 문의 처리 자동화
📊

반복 이슈 사전 예방

재발 가능성 "높음" 케이스, 특정 SW 버전에 집중되는 이슈를 AI가 자동 감지합니다. R&D에 데이터 기반 개선 요청이 가능해집니다.

데이터 기반 제품 개선
👨‍🎓

신규 엔지니어 온보딩 단축

과거 케이스가 검색 가능한 형태로 축적되면, 신규 엔지니어가 "이 증상 어떻게 해결?"을 AI에게 물어보고 바로 답을 얻습니다. 선배에게 매번 물어볼 필요가 줄어듭니다.

경험 전수 자동화
⏱️

케이스 처리 시간 단축

기존: 증상 확인 → 수동 검색 → 시행착오 → 해결.
개선: 증상 입력 → AI가 유사 케이스 + 해결법 추천 → 바로 적용. 처리 사이클이 크게 짧아집니다.

실제 활용 시나리오

1 엔지니어가 새 케이스를 받았을 때

고객: "AOI GUI가 JOB 열 때 멈춰요"
→ 엔지니어가 증상 "GUI Hang" + 카테고리 "GUI/UI" + 제품 "AOI" 입력
→ AI가 과거 유사 케이스 5건 자동 추천: "80%가 메모리 설정 문제, MaxHeapSize 변경으로 해결"
→ 엔지니어가 바로 설정 변경 → 해결 시간: 기존 2일 → 30분

2 특정 버전에서 이슈가 급증할 때

SW 3.2.1 버전에서 "Camera 연결 실패" 케이스가 2주간 8건 발생
→ AI가 패턴 감지: "3.2.1 버전 + Camera/Image 카테고리 이상 급증"
→ 자동 알림 → R&D에 데이터와 함께 리포트 전달
→ 고객 불만 확산 전에 핫픽스 대응 가능

3 고객이 Self-Resolution 가이드를 받을 때

난이도 "하" + Self-Resolution 가능 케이스 300건 축적
→ AI가 이 데이터로 고객용 FAQ / 트러블슈팅 가이드 자동 생성
→ 고객 포털에 배포: "이 증상이면 이렇게 해보세요"
→ 고객 직접 해결 → TS 팀 단순 문의 40% 감소

🎯

핵심: 지금 10분 더 쓰면, 나중에 수십 시간을 아낀다

구조화된 리포트 1건에 기존보다 5~10분 더 걸리지만, 100건이 쌓이면 AI가 패턴을 학습하고 자동 추천이 시작됩니다. 1000건이 쌓이면 사전 예방, Self-Resolution 자동화가 가능해집니다. 데이터의 품질이 AI의 품질을 결정합니다.
